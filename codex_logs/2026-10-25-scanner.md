# Scanner implementation

## User prompt

`$pstack:poteto-mode Make a scanner that recognizes identifiers, braces, parentheses, brackets, commas, colons, and semicolons.`

The user supplied poteto-mode instructions in a separate entry.

## User clarification

Asked whether identifiers should use ASCII or Unicode letters and digits.
The user answered "Use ASCII letters and digits".

## Plan and decisions

1. Ground the existing token module and grammar.
2. Compare indexed-string and input-port scanner designs.
3. Complete the throughput checkpoint before implementation.
4. Delegate scanner code, then apply and independently test it.
5. Verify behavior through the exported scan function.
6. Keep this scanner iteration on its own branch for review.

Blocking first steps were the token contract and scanner design. The scanner
has one code owner; tests are checked independently. State is local to each
call, so there are no shared writes. One module is the smallest safe unit.

Selected indexed scanning, exact string lexemes, one-based lines, no EOF token,
and keyword spellings as identifiers. LF, CR, and CRLF each count once.
No changes are made under the read-only docs directory.

## Failures and revisions

The agent limit required closing completed reviewers from the prior task.
Agent management initially used the wrong argument name; corrected to target.
The implementation uses source-length instead of shadowing the built-in length.
Filesystem writes require escalation because the session is read-only.
